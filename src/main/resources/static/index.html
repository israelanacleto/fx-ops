Operações de câmbio com ciclo de vida garantido.

O fx-ops registra operações de câmbio (par de moedas, valor, taxa e lado) e controla cada uma por uma máquina de estados, do registro à liquidação. Criação idempotente, erros padronizados e autenticação stateless.

// ciclo de vida da operação
// o que é

Um motor de domínio para câmbio.

Uma operação agrega as partes envolvidas e carrega par de moedas, valor, taxa e lado (comprador ou vendedor). O ciclo de vida não é um campo solto: é uma máquina de estados que só permite transições válidas, então uma operação liquidada nunca volta a ser cancelada, e nada muda de estado sem passar pela regra.

// recursos

Decisões de engenharia, não só CRUD.

DOMÍNIO

Máquina de estados

Transições controladas (confirm, settle, cancel) com regras no domínio, isolado do framework web.

CONFIABILIDADE

Idempotência

Criação de operações com Idempotency-Key: reenvio não duplica, devolve a mesma operação.

CONTRATO

Erros padronizados

Respostas de erro em RFC 7807 (Problem Details), consistentes em toda a API.

SEGURANÇA

Autenticação JWT

Acesso stateless com JWT e Spring Security; rotas protegidas por padrão.

DADOS

JPA sem N+1

Persistência com JPA e Hibernate, com fetch otimizado por EntityGraph para evitar o problema N+1.

OPERAÇÃO

OpenAPI e Actuator

Documentação viva em Swagger e health check via Actuator, prontos para inspeção.

// como funciona

Do login à liquidação.

A API é REST e documentada em Swagger. O fluxo típico autentica, cria a operação e a conduz pelo ciclo de vida.

# 1. autentica e recebe um JWT
POST /auth/login        { "username": "trader", "password": "trader123" }

# 2. cria a operação (idempotente)
POST /operations         Idempotency-Key: <sua-chave>

# 3. conduz pelo ciclo de vida
POST /operations/{id}/confirm
POST /operations/{id}/settle
POST /operations/{id}/cancel

Ambiente de demonstração com dados em memória. Use trader / trader123 no Swagger para experimentar.
